## 必须使用的 workflow

使用 ZCode 当前可用的原生 workflow 能力创建并运行独立的审查工作流，任务名建议为“20261025 增量审查”。不要只在普通回答中列一个计划并声称已经执行 workflow。

仓库 `.zcode/workflow-drafts/` 有历史 `.dwf.ts` 草稿，可参考当前工具所支持的调用方式；其中旧布局算法、模型、修改权限和实现循环均不是本任务指令。**不要执行或复用历史修改工作流**，不要照抄不存在的 API。先读取当前环境实际提供的 workflow 文档。新工作流仅用于只读审查，放到独立的新文件中。

主进程使用 GLM-5.3。最多创建 3 个审查 Agent 子进程；并发数和累计创建数都不得超过 3，不允许子进程继续派生 Agent，不得失败后反复创建新 Agent。通常分给下面 A/B/C 三项；无需为凑满数量创建 Agent。工具执行的测试服务与浏览器不是审查 Agent，但测试统一由主进程串行调度，避免多份浏览器、服务和全量测试同时抢资源。

如果当前环境没有原生 workflow 工具，明确写明不可用，不安装新工具、不伪造运行记录；仍按本任务书阶段串行审查，并在最终报告说明未满足原生 workflow 要求。

工作流阶段与产物：

1. **范围确认**：读取项目规则、本任务书、manifest 与相关当前源码；生成范围/分工表，区分用户要求、已有实现与待验证假设。
2. **分区审查**：最多 3 个子进程分别阅读完整相关函数及调用链，返回候选问题、反证、覆盖文件和验证建议。子进程只写各自报告，不改业务文件、不运行整套测试。
3. **主审复核**：逐条回到当前源码核对，合并同根因问题，排除旧问题与已防护路径。测试通过不等于逻辑正确，猜测也不等于缺陷。
4. **定向验证**：主进程先跑相关现有测试；必要时做极小临时复现。统一跑一次全量现有测试，按风险选择现有布局或离线验收。记录命令、退出码和关键输出。
5. **交付检查**：复查工作区变化、进程清理、审查覆盖与限制，生成中文总报告及优先修复清单。没有发现缺陷也可完成，但不能以空泛“整体没问题”代替证据。

工作流不得包含“自动修复 → 再审 → 再修”循环。复核不充分的候选可以标记待验证，无需为了得到肯定结论而扩展任务。

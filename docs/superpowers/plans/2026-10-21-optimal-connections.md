# 最优连接展示实施计划

> **For agentic workers:** 本计划在当前工作区内由本会话顺序执行；严格保留已有未提交改动和手工 `out/overlay.json`。

**目标：** 自动选择更合适的节点相对位置、边出入口与公共干线，显示更紧凑清晰的连接图。

**架构：** `layout.js` 生成并比较布局候选，基于已路由折线计算线长、交叉、折点、共享线段与移动代价；`routing.js` 选择更合适的端口方向并支持横向/纵向母线。分组布局将跨函数连接数带入文件/目录容器候选评分。新增“最优布局/手动布局”视图切换，自动模式不应用手动覆盖且不改写存档。

**技术栈：** Node.js ES modules、共享正交路由器、现有 Canvas/SVG 渲染。

---

### 任务 1：补充布局代价评估

**文件：** `src/core/layout.js`

- [ ] 增加确定性的正交折线评分，统计可见线段并集长度、非端点交叉、折点数、包围画布面积和偏离原布局的代价。
- [ ] 让 `layoutPartitioned` 为每个可行折行数生成完整坐标候选，把跨组边数量和同源/同目标共享干线收益纳入原宽高比评分。
- [ ] 对小型函数图比较纵向、横向两种层级方向；按节点度数顺序做有限轮次的局部位置搜索，候选仅放在相邻节点四周且不得与其他节点相交。
- [ ] 对大图关闭局部搜索，只比较纵/横基线并使用稳定排序；限制候选上限，避免全排列或无界迭代。

### 任务 2：根据优化位置分配端口和母线

**文件：** `src/core/routing.js`

- [ ] 自动边在未指定 `fromSide`/`toSide` 时评估上下左右组合；代价计入出口是否朝向目标、节点避障、已布线段交叉、长度、折点和可共享干线收益。
- [ ] 保留显式端口方向为硬约束。
- [ ] 复用现有 `routeBus` 的事务式校验方式，新增左右出入边共享竖向母线；母线不通时逐边回退。
- [ ] 继续保留原有同端点重复边重合展示与原边数据，不合并语义对象。

### 任务 3：保留分组容器与手工布局

**文件：** `src/core/layout.js`、`src/server.js`、`web/app.js`、`web/index.html`、`web/i18n.js`

- [ ] 将跨函数边的计数传给目录层级布局评分，避免文件对之间只剩一个无权重关系。
- [ ] 对函数位置候选限定在所属文件框内部；外层文件/目录候选重算容器矩形并检查兄弟容器不重叠。
- [ ] 增加默认开启的“最优布局”开关，切到手动布局后恢复服务端已保存的位置、手动边和端口设置。
- [ ] 服务端自动视图不应用手动坐标、手动边和手动端口覆盖，但保留删除状态和节点标记，且不写改 overlay。

### 任务 4：交付可见结果

**文件：** `src/core/layout.js`、`src/core/routing.js`

- [ ] 用现有 TCU 数据生成新的 SVG 预览，使用新文件名保存，保留现有 `bus-after.svg`。
- [ ] 检查同一跨文件扇出在横向候选下是否改排右侧并共用竖向主干；检查复杂/阻挡场景是否能回退到合法正交线。
- [ ] 不提交本轮代码；最终报告改动文件、可视化结果和剩余限制。

# C 工程 before / after 差分可视化实施计划

> **给执行者：** 按下列复选步骤在当前分支内执行。用户已允许使用 Luna 子代理；只把独立的示例准备与页面控件工作交给它，主代理负责比较语义、接口和整体验收。已按本计划实现，验收记录见文末。

**目标：** 选择两份 C 工程，自动识别函数、全局变量与文件作用域静态变量的新增、修改、删除，按当前图形规则呈现，并展示调用关联及共享变量带来的潜在影响。

**架构：** 分别建立 before / after 的现有 C 索引和数据流索引，以代码定义对齐、比较，再生成包含已删除对象的比较模型。比较结果进入现有视图与 ELK 排版；比较分类是派生数据，不批量写成 after 工程的人工标注。

**技术栈：** 现有 Node.js、Electron、C 词法分析器、轻量预处理器、tree-sitter C、ELK、原生页面模块和 `node:test`，不加依赖。

## 1. 范围、非目标与不改动范围

本次实现：

- 两个本机目录的显式选择与比较；支持 `xxx_befor`、`xxx_before`、`xxx_after` 等任意目录名，不靠后缀判断版本。
- C 的函数完整定义、文件作用域变量完整声明和初始化表达式比较。
- 宏变化导致展开后的函数/变量定义变化，即使使用处的原始文本未改变，也能识别。
- 调用关系、变量读写关系的新增与删除；保留旧关系及其 before 位置。
- 以直接变更为起点，找出潜在受影响函数和变量，并给出关联依据。
- 一套能人工检查、也能供现有测试工具读取的 before / after C 工程。

非目标：

- 不实现 C++ 支持、自动重命名/移动猜测、编译器级语义等价判断或完整指针别名求解。
- 不新增局部变量、结构体成员、宏的专用画布节点；局部变化归入函数，宏变化列入摘要与原因。
- 不承诺覆盖运行时函数指针目标或所有编译配置。结构体、枚举、typedef 等未能归属到函数/变量的变化，至少列为文件层面的未归属变更，不静默忽略。
- 第一版不新增比较历史数据库、比较会话导入导出、命令行比较或完整源码差分编辑器。

不改动：现有四色语义、函数/变量边框、实虚线规则、ELK 布局算法、普通工程标注与数据库结构，以及原 `S:\流程图` 工作区。

## 3. 比较口径

### 定义对齐与分类

- 函数沿用 `相对文件路径::函数名` 对齐；全局变量沿用 `var::名称`，文件私有变量沿用 `var::相对文件路径::名称`。不把绝对根路径或行号作为身份。
- `extern` 声明与定义合并时以真实定义为准；一条声明里有多个变量时，分别比较每个声明符、共用类型限定信息及各自初始值。
- 函数比较返回类型、参数声明、修饰及函数体；变量比较类型、存储限定、指针/数组声明和初始化表达式。
- 比较词法 token 的类型和值，忽略注释、空白和位置；字符串/字符字面量、数字和操作符必须保留。
- 同时记录原始定义与展开后定义的指纹。原始定义变化记为“定义修改”；原始相同、展开结果变化记为“宏展开变化”，两者画布分类均为 `modified`。
- 仅 before 有为 `deleted`，仅 after 有为 `added`，两侧相同为 `existing`。
- 移动或重命名先按删除与追加处理，并在说明中明确，避免错误配对。

### 关系比较

- 函数调用按“调用方、被调用方、画布关系类别（函数调用/变量访问）、规范化条件”对齐，不按调用行号对齐。直接调用、宏调用、函数指针调用的来源差异保留在两侧调用证据中；目标不变时不凭来源变化新增图关系。
- 同一函数对的重复调用保留两侧次数和调用位置；仅次数变化不把整条关系误判为删除再新增，所属函数仍按定义变化标黄。
- 变量关系另包含“读 / 写 / 读写”口径；访问方式变化可保留旧关系与新增关系，虚实线仍只表达关系种类。
- 新增边沿用红色，删除边沿用原色加叉号；变量关系始终是虚线，不借虚线表示删除。
- 聚合比较边时区分关系状态，防止同端点的新增/删除关系被 `subgraph` 合并。

### 潜在影响与上下文

1. 在 before 和 after 中分别进行分析，最后合并结果；禁止把旧版写者与新版读者交叉拼成某一版本从未存在的数据链。
2. 变更函数向上沿调用关系找直接、间接调用者；沿其写入的共享变量找读取者，并继续查相关调用者与数据依赖，使用访问集合终止循环。
3. 变更变量沿读写引用找到相关函数；类型与初始值变化先保守地列出相关访问者，不宣称业务结果必然改变。
4. 被变更函数调用的函数另列为“被调用上下文”，不一概说成自身发生变更。默认至少呈现一层，并复用已有上下游展开操作。
5. 节点的四种变更分类与“潜在影响 / 调用上下文”分开存放。未改代码的关联节点保持既存浅绿，不加第五种底色。
6. 每个关联结果保留来源版本、起点和关系依据，详情可解释“因谁调用 / 经哪个变量关联”。
7. 分析结果完整计算；画布沿用已有节点数量限制。若截断，明确显示已展示数/结果总数，不能声称全部呈现。

## 4. 结果结构与会话边界

新增 `src/core/compare.js`，对外提供 `compareProjects(beforePath, afterPath)`。核心结果结构固定如下，具体容器可按现有 Map/数组习惯实现：

```js
{
  beforePath,
  afterPath,
  model, // 两侧定义和关系的并集，匹配对象优先使用 after 元数据
  beforeModel,
  afterModel,
  summary: {
    functions: { existing: 0, modified: 0, added: 0, deleted: 0 },
    variables: { existing: 0, modified: 0, added: 0, deleted: 0 }
  },
  roots: [], // 直接变更及关联展示的入口，允许包含变量
  warnings: []
}
```

比较节点及边附带 `change`、两侧位置 `locations.before/after`、`reasons` 和 `versions`；未变关联节点另带 `impact` 或 `context`。只向页面发送必要元数据，不发送 AST 或循环对象。

- before / after 各自先完成索引；比较模型不得重新用 after 目录构建数据流，否则删除对象和旧关系会丢失。
- 数据流查询分别调用两侧现有分析后合并显示，保留版本，不把两侧 readers/writers 简单混成一份再作笛卡尔连接。
- 比较成功前不替换当前工程。路径不存在、两侧为同一真实目录、无可解析 C 文件时，返回具体原因，当前工程保持可用。
- 复用现有切换互斥。比较视图带会话标识，增量布局不能复用普通视图或上一对目录的画面。
- 第一版比较会话只用于查看、筛选、定位和展开；不把自动分类落库。比较期间不改普通工程的人工分类、删除记录、历史与最近正常视图；服务端拦截这些写入，页面关闭对应编辑入口。
- 退出比较后通过既有工程切换流程普通打开 after；恢复该工程原有标注与正常视图。服务重启后不自动恢复比较会话。

## 5. 页面入口

在现有“选择工程”窗口加入“普通工程 / 工程比较”选项，比较区域包含：

```text
工程比较
修改前 before  [目录绝对路径                 ] [浏览]
修改后 after   [目录绝对路径                 ] [浏览]
                                             [开始比较]
```

- 浏览按钮通过新增的 `callgraph.chooseDirectory()` IPC 仅返回目录或 `null`，不启动/切换工程；使用现有可信窗口校验方式。
- 浏览器打开页面时保留绝对路径输入，不新增源码上传流程，不使用拿不到服务器绝对路径的目录文件上传代替本机选择。
- 比较中禁用重复提交；取消浏览不清空已填路径；失败保留两侧输入及当前图。
- 成功后顶栏显示 before → after、直接变更数量和“退出比较”；默认展示变更及关联，不依赖某个 main 能否调用到所有变更对象。
- 无差异明确显示“未发现函数、变量或关系变化”；只有变量变化、只有删除对象、无入口函数也能生成结果。
- 详情增加变更原因与两侧文件/行号；不建设新的源码编辑器。
- 表单文案通过现有 `web/i18n.js` 接入，中文与日文键保持齐全。
- 当前画布导出 SVG 可直接复用已有前端样式；不在第一版扩展服务端/命令行比较报告。比较模式中不提供尚未适配的会话导出与历史编辑入口。

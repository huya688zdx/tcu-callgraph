# 大工程加载性能验证

## 2026-11-23：首次打开、批量添加和选中动画

以合并 PR #15 后的 `783131f` 为基线，在 Linux 和 Node.js 24.19.0 上打开同一份合成工程。样本共 5,618 个文件、10,958 个函数、12,884 个变量、48,290 条关系、51,944 条调用记录和 24,505 个宏。两版的统计和索引明细一致。

冷开复用一次扫描得到的文件清单，每个文件只词法分析一次。扫描完成后退出解析进程，操作系统回收该进程的内存。就绪日志附带文件清单、缓存读取、源码分析或索引重建、缓存写入的分段用时。

| 服务指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 冷开到服务就绪 | 8.69 秒 | 4.22 秒 |
| 冷开期间进程树峰值 RSS | 788 MiB | 713 MiB |
| 冷开就绪后服务 RSS | 760 MiB | 249 MiB |
| 解析缓存重开到服务就绪 | 0.63 秒 | 0.72 秒 |

用无头 Chromium 验证批量添加 480 个函数。预览用时从约 4.0 秒降到 70 ms，确认后均有 481 个节点和 1,280 条关系。确认后的完整 ELK 排版约需 6 秒。新图显示后，批量提示静止期间的连续刷新从约 30 帧/秒降到 0。新增关系保留原有的合并方式。

在另一张 480 节点、1,200 条关系和 300 个标签的图上，以 2 倍设备像素比复测选中动画。箭头和函数虚线边框由单独画布绘制。长线动画每秒约复制 7,513 万个底图像素，修改后底图复制为 0，动画层每秒约清除 122 万个像素。线段和函数动画的第 95 百分位帧间隔均从约 33 ms 降到约 17 ms。

同一张图完整显示在视野内时，平移复用已绘制的画面，松手按最终位置重绘。保持选中长连线并注入 200 次平移事件，底图重绘从 62 次降为 1 次，第 95 百分位帧间隔从约 50 ms 降到 17 ms。放大后，进入视野的新内容随平移绘制。

服务耗时以服务就绪为止。画布数据测量软件渲染时的帧间隔和绘制量。Windows 实机的 BAT 总耗时、应用总内存和 GPU 占用率需在实际工程中验证。

## 2026-11-23：大工程内存与画布拖动

扫描按文件保留宏的修改记录，收齐定义后再解析调用和变量引用。索引保存调用顺序检测需要的结论，函数体 token 和变量分析用的语法树在各自阶段结束后释放。旧解析缓存会自动重建。工程概览只请求计数。

画布平移和缩放复用标签的位置，只绘制与视口相交的对象。拖动事件按帧处理，松手时会先应用最后一次位移。选中动画只合成受影响的区域，静止时约每秒 30 帧，窗口隐藏时暂停。同类批量选中保留所有选中高亮，动画集中在当前选中项。

以 `5533091` 为基线，使用 Linux、Node.js 24.19.0 和同一份合成 C 工程。样本有 944 个文件、13,056 个函数和 41,216 个宏。两版的 Node 堆上限均为 4 GiB，峰值为服务进程的 RSS。画布使用 Chromium 和另一份固定图，其中有 480 个节点、1,200 条关系、300 个标签。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 服务冷启动峰值 RSS | 3,451 MiB | 589 MiB |
| 服务冷启动至就绪 | 20.62 秒 | 2.73 秒 |
| 同一数据库重开至就绪 | 19.18 秒 | 0.42 秒 |
| 120 次平移事件触发的重绘 | 120 次 | 24 次 |
| 单条连线脉冲每帧复制的画布面积 | 100% | 约 0.57% |

服务耗时为单次同条件测量。画布指标来自无头 Chromium，可复查绘制量和响应时间。Windows 实机的 GPU 占用率需要在对应机器上测量。

## 2026-10-26：普通调用图按需加载变量

普通工程打开时不再预建全工程 AST 变量读写索引，页面首屏也不再自动请求全量变量清单。
调用图遍历时排除变量边，避免变量占用函数节点限额或参与默认排版。选中文件框或目录后，
点击「加载全局变量」获取清单，勾选需要的变量加入画布；右键数据流查询和显式保存过的变量选择
仍会按需启动分析。分析完成后更新完整缓存，旧的完整分析缓存也继续复用。
C 工程检查或清理失效标注前也会按需补全变量索引，避免将尚未分析到的 typedef 变量误判为已删除。
源码读取或解析不完整时拒绝清理，不以部分结果覆盖正常缓存；等待分析时工程已切换则拒绝旧请求。
DOT/GV 导入图使用自带的完整节点和连线索引，不执行 C 变量分析，也不受此前 C 分析失败状态影响。
工程比较仍保留变量差分。变量取消、重新勾选时复用未被移动的空位，避免反复增量排版漂移。

Linux、Node.js 24.19.0，同一合成 C 工程（400 文件、8000 函数、800 个变量），
修改前后各用全新临时数据库启动一次；不含浏览器启动和 ELK 出图时间：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 冷启动至服务就绪 | 3641 ms | 1015 ms |
| 源码 readFileSync 次数 | 800 | 400 |
| 源码读取字节数 | 989780 | 494890 |
| 进程峰值 RSS | 365.9 MiB | 170.7 MiB |

读取次数和字节数由临时预加载脚本拦截源码 readFileSync 统计；峰值 RSS 来自
process.resourceUsage().maxRSS。不是物理磁盘吞吐或 Windows 磁盘活动率测量，
不表示所有机器都会有相同提升。首次源码调用索引、完整缓存反序列化、ELK 大图排版仍有成本；
主动查询变量时仍需完整分析，没有实现逐文件增量解析。

新增回归覆盖首屏未触发 AST、显式勾选变量、缓存重开后的纯函数默认视图和节点限额。
Chromium 验证首屏无 /api/vars 请求，主动加载与勾选/取消、工程切换清空变量清单均正常。

- [rusEFI](https://github.com/rusefi/rusefi)：包含 `firmware/controllers/tcu` 变速箱控制代码，提交 `54d4fcdbae0a356d9c352ed7474f746109fb3116`，扫描 `firmware`，共 1658 个 C/C++ 源码及头文件；未拉取子模块。
- 自动生成的 C 工程：10000 个文件、20000 个函数、30000 条关系、10000 个变量，用于补足万文件规模。

公开源码只用于读取和分析，保存在忽略目录 `.verify-tmp/public/`，未并入产品，也未执行它们的构建脚本。公开工程包含 C++，这里的函数计数指当前分析器识别结果，不代表新增了完整的 C++ 语义支持。

## 修复内容

原缓存以展开后的 JSON 大小限制为 40 MB。rusEFI 的 JSON 约 124 MB，因此每次打开都无法命中缓存；即使小工程命中，AST 变量读写索引也会重新构建。

现在使用 Node 内置二进制序列化保存完整分析结果，包括 Map、Set 和变量读写行号；不保存 `_index` 引用表和 Promise。磁盘上按压缩后的大小限制，rusEFI 实际缓存约 11.0 MiB。缓存键已变更，旧的派生缓存会重新生成，标注和工程状态不受影响。

文件树只在展开或定位文件时创建该文件的函数行；未展开文件的勾选和入口顺序继续保留。加载日志也改为包含 AST 分析和缓存写入耗时，避免原日志少报等待时间。

## 实测结果

以下为同一源码、已有缓存后，重新启动独立服务进程，到服务就绪的墙钟时间；不包含 Electron 窗口启动与 ELK 出图时间。数字会受磁盘缓存、杀毒扫描和同时运行的程序影响，不能视为所有机器的保证值。

| 工程 | 优化前重开 | 优化后重开 |
| --- | ---: | ---: |
| Ultimate NAG52，174 文件 | 2.80 秒 | 0.35 秒 |
| rusEFI firmware，1658 文件 | 69.65 秒，无法命中缓存 | 1.75 秒 |
| 合成 C 工程，10000 文件 | 4.65 秒 | 2.02 秒 |

万文件文件树另测：每文件两个函数，首次构建含强制布局，从约 695 ms 降至 328 ms；DOM 元素从 110505 个降至 50505 个。

优化前后函数、关系和变量计数相同，变量接口明细的 SHA-256 相同。单元回归验证完整分析缓存的读写集合、函数体、关系和调用顺序建议；界面验证按需展开、定位、取消勾选及保留未展开文件的选择。原始测量记录保存在 `out/performance/`。

## 使用与边界

升级后第一次打开需要重建缓存。首次打开、源码修改后的全量分析仍可能较慢；本次没有加入逐文件增量解析。没有通过少扫描文件、截断变量或减少连线来换取加载速度。ELK 布局规则保持不变。

# C 工程差分样例

本样例有三个目录：

- `project`：总代码工程，先用应用普通打开这个目录。
- `before`：修改前的局部对照文件。
- `after`：修改后的局部对照文件。

打开 `project` 后，点击左上角工程按钮 → “工程比较”，确认“总代码目录”显示的是 `project`，再分别浏览选择 `before` 和 `after`，点击“开始比较”。解析完成后，在弹窗中勾选要加入的函数或变量，再点击“加入当前图”；取消不改变原图。浏览器版可以直接填写这两个对照目录的绝对路径。

对照文件保留相对于总代码目录的路径；未出现在 before 和 after 中的文件沿用总代码工程内容。已进入对照范围但只在一侧存在的文件表示新增或删除。分析只替换内存中的文件来源，不覆盖总代码目录中的文件。

比较图沿用现有四色与连线规则，点击函数或变量可查看两侧位置及变更原因。比较模式只供查看，点击“退出比较”回到 `project` 总代码工程及其原有标注。

## 预期差异

| 对象 | before / after | 预期 |
| --- | --- | --- |
| `Normalize`、`Monitor_Read`、`main`、`Supervisor_Read` | 定义相同 | 既存（4 个函数） |
| `Sensor_Update` | 源码相同，`SCALE` 从 10 变为 20 | 既存，单独提示宏展开影响 |
| `Control_Read` | 超限时调用 `Legacy_Log` / `Diagnostics` | 修改；旧调用删除、新调用新增 |
| `Legacy_Log` / `Diagnostics` | 仅 before / 仅 after | 删除 / 新增 |
| `g_rpm` | 两侧初始化均为 0 | 既存（1 个变量） |
| `g_limit` | 初始化从 100 变为 120 | 修改（1 个变量） |
| `g_legacy` / `g_fault` | 仅 before / 仅 after | 删除 / 新增 |

预期函数并集：既存 5、修改 1、新增 1、删除 1（共 8 个）。预期变量并集：既存 1、修改 1、新增 1、删除 1（共 4 个）。勾选全部候选项可查看这 12 个节点，初始不自动替换画面。

`project/main.c` 和 `project/observer.c` 都不在 before/after 中。`main` 是调用入口；`Supervisor_Read` 位于 `observer.c`，读取 `Sensor_Update` 写入的 `g_rpm`，与 `Sensor_Update` 没有直接调用关系。比较图仍应显示这两个仅在总代码工程中的函数，并将它们保留为既存分类，详情列出潜在影响依据。

# 公共变量关系样例

运行 `node src/server.js samples/shared-state`，或用应用打开此目录。

`Sensor_Update` 与 `Control_Read` 没有相互调用。前者写公共变量，后者读取它们；`main` 只负责分别调用两个函数。

| 操作 | 右侧预期关系 |
| --- | --- |
| 右键 `Sensor_Update` → 数据流分析 | “数据去向”显示 `Sensor_Update → g_rpm → Control_Read`，另有 `g_index`、`g_samples` 两条链 |
| 右键 `Control_Read` → 数据流分析 | “数据来源”显示相同的三条链，箭头始终从写入方指向读取方 |
| 分析 `Debug_Echo` | 无公共变量关系，同名形参不算全局变量 |
| 查看两个文件的 `s_count` | 各自独立，不会把两个函数连起来 |

查找结果显示在右侧“数据流分析”，同时列出来源和去向，不生成浮框或画布预览。选择一条关系，点击顶部“加入画布”，或直接双击关系行；已加入时，同样操作可移出该引用关系，共用的节点和其他引用保留。加入和移出均由 ELK 重新排布，沿用正式节点和连线样式。结果列表支持按变量、函数、文件筛选，关闭结果不会移除已加入的内容。文件树里不在画布中的函数也可通过右键直接分析。

`Scale(g_rpm)` 是按值传参，只记录 `Control_Read` 读取 `g_rpm`；不会将它判为写入方，也不会给 `Scale` 添加公共变量读取边。`g_samples[g_index]` 还会独立记录对下标 `g_index` 的读取。

这是按变量聚合的静态读写关系，用于发现可能的数据依赖，不证明运行时先后顺序。结构体成员、数组元素目前仍聚合到所属变量；显式取地址按“读和可能写”保守处理，尚不追踪跨函数指针参数和宏展开中的变量访问。
